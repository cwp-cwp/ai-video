# AI 短剧导演（外部编排）

本 skill 把「AI 视频创作平台」当成**渲染后端 + 资产库**，由你在外部承担**导演、编剧、摄影指导**的创作决策。

它给你三件事，别混淆：

| 用法 | 什么时候用 | 看哪章 |
|---|---|---|
| **A. 全流程跑通**（基础功能） | 从小说一路做到成片。和页面上点那排批量按钮等价，只是不用手点 | 第 **1–9** 章 |
| **B. 质量增强**（把"能用"改成"好看"） | 平台已经生成了剧本/分镜，你想修台词时长、描述、景别、提示词 | **第 Q 章** |
| **C. 精品线**（把"粗剪"改成"成片"） | 平台产出的成片剧情跳跃、像拼贴。**做法是在系统生成的剧本/分镜基线上做增量优化**，不是自己重写 | **第 D 章（尤其 D.0.5）** |

> **B 解决单镜好不好，C 解决整片顺不顺。** 只做 B 做到头，也就是"每镜都不错但串起来还是平的"——
> 剧情丢失、场与场硬跳，是结构问题，必须在 D 章解决。

**平台把流程和提示词固定死了，它不会自我批判。** 你在它产出之后介入，只改**字段**——
`description / shotType / duration / cameraMovement / soundEffect / 提示词 / 台词`——
这些是喂给视频模型的输入，**输入更好，成片就更好**。这就是外部 agent 叠加在固定系统之上的价值。

全流程（用法 A）的骨架：

```
① 建项目 → ② 分集规划（切分小说 / 建好全部分集 / 各存各的片段）
          → ③ 逐集跑：剧本 → 资产 → 分镜 → 调度 → 提示词 → 视频
              ↑ 做完一集再做下一集，不要把所有内容塞进第一集
```

## 起手式：先确认用户给了什么

用户至少要提供 **小说文本 + 账号密码**，服务地址一般可自动探测。收到后**先通读、先规划，再回计划**：

```
通读：全文 N 字，情节点 X 个，主线是「一句话」
分集：建议 K 集（第1集 <起>—<止> 约 60s｜第2集 <起>—<止> 约 70s｜…）
项目：<剧名>｜<连续剧/AI短剧>｜<16:9/9:16>｜<视觉风格>
计划：先建 K 个分集并切分原文 → 做完第 1 集给你看 → 确认后继续第 2、3…集
```

**三件事不要省**：

1. **先判断要不要分集**（第 2 章）——不分集硬塞，后面必然只做出一部分
2. **不要一上来就跑全片**——先做 10–15 镜的可看片段确认风格，省钱且不返工
3. **交付一集算一集**——不要 10 集全做完才发现风格不对

> 上面是格式示范，**数字和分集数量必须按实际小说算**，不要照抄。
> 项目三要素（类型/比例/风格）一定要问用户，选项见第 1 章。

## 0. 前置（每次会话只做一次）

### 0.1 确认服务地址

| 部署方式 | Base URL |
|---|---|
| 便携启动器（Tomcat，默认） | `http://localhost:18080/video-service/api` |
| 本地开发（Vite 代理） | `http://localhost:8090/api` |
| 线上 | `https://<域名>/video-service/api` |

先探活：`GET {base}/auth/login` 之类返回 JSON（不是 404）即说明服务在线。

### 服务需要重启时 —— **不要自己动**，让用户来

后端**没有**取消 / 停止任务的接口（只有 `GET /running-tasks/{projectId}` 可查）。所以要中断一个正在跑的批次，只能重启服务。

**你不要执行 `stop.bat` / `start.bat`，也不要杀进程、不要自己拼 java / catalina 命令。** 直接告诉用户：

> 需要重启一下服务：请**先双击 `stop.bat`，等它的命令行窗口自己关掉之后，再双击 `start.bat`**。
> （stop 之后立刻 start 会端口冲突 18080 / 13306，必须等旧进程真正退出。）

用户重启完你再继续，探活方法同上（`GET project/list` 能返回 JSON 就说明好了）。

补充：

- **重启会中断正在跑的异步任务**（任务在内存里）。已完成的镜头结果已落库、不会丢；未完成的要重新提交。
- 🚫 **绝对不要往 `apache-tomcat-10.1.59/` 目录里写任何文件**——日志、脚本、临时文件、`*.txt`、`*.log`、备份，一个都不行。这是交付给用户的便携软件包，多一个文件就污染了，用户自己没法排查。所有日志 / 临时产物写到**自己的临时目录**（如 `<工作目录>/_tmp/`），只调用它的脚本，不改它、也不往里放东西。
- 🚫 **`skills/` 目录（含 `skills/scripts/`）同样一个临时文件都不许放**——它是提交进仓库的 skill 本体，一次性补丁脚本、监控脚本、分镜快照 JSON、日志、备份都不行，会污染仓库 diff。agent 需要复用 `scripts/drama.py` 时，在自己的临时脚本里 `sys.path.insert(0, "<skills/scripts 绝对路径>")` 后 `import drama`，或直接 `python "<绝对路径>/drama.py" <命令>` 调用，**不要把脚本拷贝进 skills**。自己产生的临时脚本 / 文件一律放在 agent **自己新建的 `<工作目录>/_tmp/` 目录**里，任务结束后清理掉。两个细节：
  - `import drama` 会在 skills/scripts 下生成 `__pycache__`，同样算污染——跑自己的脚本时加 `python -B`（或环境变量 `PYTHONDONTWRITEBYTECODE=1`），跑完检查并删掉已生成的 `__pycache__`。
  - 例外：`skills/scripts/.session.json` 是 `drama.py login` 自动生成的登录态文件（skill 自身运行时产物，drama.py 靠它免重复登录），允许存在；除此之外一个文件都不许多。

### 0.2 登录

```bash
POST {base}/auth/login
{"email":"...","password":"..."}
→ {"code":0,"data":{"token":"...","id":123,"nickname":"..."}}
```

**之后每个请求都必须带 `X-Token: <token>`**（不是 `Authorization: Bearer`，这一点平台前端也是这么做的）。
响应统一是 `{code,msg,data}`，**只有 `code == 0` 才算成功**，HTTP 200 也可能带业务错误。

用脚本可以省掉这些重复劳动（推荐）：

```bash
python scripts/drama.py login --base http://localhost:18080/video-service/api --email a@b.c --password xxx
python scripts/drama.py get project/list
```

> ⚠️ **Windows Git Bash 坑**：以 `/` 开头的参数会被 MSYS 当成文件路径转换（`/project/list` → `D:/.../project/list`）。
> 所以脚本里的接口路径**一律不带前导斜杠**（写 `project/list`）；PowerShell / cmd 下带不带都行。脚本检测到被转换会直接提示。

### 0.3 向用户确认三个选项

项目类型 / 视觉风格 / 画面尺寸，**系统的可选值见第 1 章开头的表格**，必须让用户从里面选。
不要自己编风格词（写「电影感写实」「国风工笔」这类不在选项里的值，下拉框会显示空白）。

## Q. 质量增强层（本 skill 的核心价值）

全流程只是"跑通"。这一章解决跑通解决不了的事：**同一个分镜，怎么让它拍得出来、台词说得完、有电影感。**

### Q.1 核心循环

```
基线（平台已生成的 剧本 / 分镜 / 资产）
   │ ① GET 拿下来
   ▼
② 体检 ── 程序化（drama.py audit）+ 导演（cinematic-rules 第八节自检）
   │     → 问题清单：镜头 + 字段 + 为什么差 + 怎么改
   ▼
③ 改写 ── 逐字段创作决策（Q.3 给配方）
   │
   ├─→ ④ 整包 PUT 回写（save-storyboard，P0 自动拦截）
   ▼
⑤ 复检 ── 再跑一次 audit，P0/P1 必须变少；没达标回 ③
```

三条纪律：

1. **只改"能一句话说清为什么更好"的字段**——说不出理由就不改，别为改而改。
2. **改完要能看到指标下降**（P0/P1 条数），否则是自嗨。
3. **先剧本后分镜**——分镜建立在剧本之上，剧本平则分镜平。

### Q.2 体检（先找"能算出来的病"）

```bash
python scripts/drama.py audit --project {projectId}                     # 体检服务器上的分镜
python scripts/drama.py audit --project {projectId} --file shots.json   # 体检本地改好的文件
python scripts/drama.py audit --project {projectId} --out report.json   # 完整报告存 JSON
```

> `--project` 要和分镜的实际归属一致（连续剧用**分集 id**），否则资产名校验会拿别的项目的资产比。

#### 输出一：台词 vs 时长表（最关键，先看它）

```
=== 台词 vs 时长（舒适 4 字/秒，>5.2 字/秒会截断/急促）===
  镜号  字数  时长   字/秒   需秒   判定
  1     21    5s     4.2     5.2    偏急
  2     21    4s     5.2     5.2    截断/急促
  3     63    15s    4.2     15.8   必须拆镜
  4     14    12s    1.2     3.5    偏拖
```

| 判定 | 含义 | 怎么改 |
|---|---|---|
| `必须拆镜` | 按 4 字/秒超过 15 秒，**一镜装不下** | 按句号/呼吸点拆成 2–3 镜（加时长无效）|
| `截断/急促` | `字数 ÷ 时长 > 5.2`，超语速上限 | 时长提到 `字数 ÷ 4`，或把这句拆到下一镜 |
| `偏急` | 没超上限，但 `时长 < 字数 ÷ 4` | 补到 `字数 ÷ 4` 秒 |
| `偏拖` | 不到 2 字/秒，话说完了镜头还空着 | 缩短时长，或补动作/反应 |
| `OK` | 4 字/秒上下 | 不用动 |

**硬水位线：60 字**（15 秒 × 4 字/秒）。一句台词超过 60 字就注定一镜说不完——**先拆，再谈时长**。

#### 输出二：P0 / P1 / P2 问题清单

| 级别 | 含义 | 典型条目 |
|---|---|---|
| **P0** 阻塞 | 写坏数据或出不了片，**save 会被拦** | `shots` 空、`shotNumber` 不连续、描述空、时长缺失、资产名对不上、缺 `sceneAssetId`/`characterAssetIds` |
| **P1** 质量 | 影响成片，建议全部修掉 | **台词说不完/太急促**、动作超载、抽象词/心理描写、总长偏离目标、续接全关 |
| **P2** 建议 | 有余力再改 | 近景没角色、声音空、提示词空、景别+运镜+场景三同（真看不出切镜）、景别过于单一、全片固定机位、跨场还开着续接 |

> **连续同景别不是错**：长对话、正反打、长镜头本来就会在一个景别里待很久，只要机位/角度有变化就是正常切镜。
> 只有「景别 + 运镜 + 场景」三件完全一样，观众才看不出变化——这也只是提醒，不是缺陷。

#### 导演体检（程序算不出来的，过 `reference/cinematic-rules.md` 第八节）

- **可拍性**：每镜能写出「起点 → 唯一动作 → 终点」吗？写不出就是描述在飘。
- **节奏**：每 8–12 镜有没有一次"呼吸"（空镜/静止/环境声）？
- **衔接**：出画/入画方向、视线匹配、续接逻辑对不对？
- **情绪外化**：情绪是可见动作/表情，还是形容词？（"她很绝望"拍不出来）

### Q.3 逐字段改写（核心创作）

按"对成片影响从大到小"改。每改一镜对照体检：这一镜的 P1 应该少一条。

**① `description` —— 影响最大**
平台多是"谁在干嘛"的白描，改成**能拍出来的具体镜头**。
配方：`起点 → 唯一动作（触发/接触/落点）→ 次级反应 → 终点`，全用可见事实。

| 平台写的（偏平） | 改写后（可拍） |
|---|---|
| 林砚在巷口看着怀表，心里很复杂 | 林砚站在巷口，左手捏着怀表，表盖在指间摩挲两下；他抬眼望向巷尾，眼神定住 |
| 她感到很绝望 | 她慢慢蹲下去，一只手撑着墙，手指抠进墙皮 |
| 两人激烈争吵 | 拆正反打：他往前一步逼近，她后退半步；他抬手指向门口，她死死攥住手里的杯子 |

**删掉所有结论词和内心词**：`很美/震撼/电影感/氛围/高级`（拍不出来）、`心里/想到/回忆起/意识到`（镜头拍不到）。

**② `shotType` —— 按"必须被读到的信息在哪个尺度"分配**
决策表见 `cinematic-rules.md` 二·2。速记：证据在指节上 → 大特写；后果在两人距离上 → 全景；决定/被藏住的反应 → 近景。
竖屏（9:16）以中景/近景/特写为主，空间用**纵深分层**交代，远景全景少用。
体检里「景别+运镜+场景三同」「景别过于单一」可以看一眼；**单纯连续同景别不用改**（长对话/正反打就该这样）。

**③ `duration` —— 先保证台词说得完**（判定表和阈值见 Q.2）

- `镜长 = 台词字数 ÷ 4 + 必须看清的动作 + 反应留白`
- 台词超了 → **拆到说话者/听者两镜，别让人物加速**（加速最露馅）
- 一段完整的话 / 一个完整动作 = 一镜，哪怕 10–12 秒（单镜上限 15 秒）
- 别为"画质稳"把长对白无意义地拆碎——接缝比画质损失更伤

**④ `cameraMovement` —— 按"这镜在做什么"选**
决策表见 `cinematic-rules.md` 二·3。速记：人物移动→跟/横移；新信息进来→摇/拉；一句话压到人→缓推；爆发/反转→短促推近；观察/等待→固定。
**固定是最后一行，不是默认**，选固定要能说出理由。一镜只做一个运动。

**⑤ `soundEffect` —— 空着就填具体声源**
写 `雨打铁皮棚、远处电动车驶过`，不是"环境音"。三层：环境底噪 + 动作音效（开门/摔杯）+ 情绪音。
关键动作必须有动效；高潮前可抽静音。

**⑥ 提示词（`h3VideoPrompt` / `msrVideoPrompt`）**
结构见第 7 章。质量增强的重点：**动词具体**（"手指在表盖上摩挲两下"不是"看着表"）、
**光写方向+质感**（"左侧窗光，硬光"不是"光线充足"）、**情绪外化**、默认声明画面内不生成字幕文字。
注意两种格式别搞混：**H3 是 3000–6000 字符的结构化长提示词**（含 `<Subject N>`/`<Picture N>` 绑定和 `[Shot N] At mm:ss` 时间轴），不能压缩；只有旧的 `msrVideoPrompt` 才是 60–120 字短文本。

**⑦ 剧本（若剧本也是平台生成的，先改它）**

- 每场只承担一个戏剧功能，功能重复的合并
- 对白写潜台词：每句问"想让对方做什么"，答不上就删
- 每句台词能变成演员的一个动作/表情，转不成的改写（去 AI 味最有效）
- 开场即钩子，结尾落在画面而不是旁白
- 命名逐字一致（后面建资产、分镜引用全靠字符串匹配）

### Q.4 回写（整包覆盖，小心）

分镜保存是**整包覆盖**：GET 全量 → 改 → 整体 PUT。只传改的镜头会删掉其他镜头。

```bash
python scripts/drama.py save-storyboard --project {projectId} --file shots.json
```

内置 **P0 拦截**：有 P0 就拒绝写库（避免把分镜写坏）；P1 只提示不阻塞。

回写铁律：

- **原样保留平台写的字段**：`videoUrl`/`firstFrameUrl`/`videoStatus`/`sceneAssetId`/`characterAssetIds`/`propAssetIds`，别自己编 id
- **别显式写有默认值的字段**：`usePrevVideoRef`(true) / `prevVideoFrames`(5) / `selectedSceneView`
- **改了 `description` 就必须重跑"调度 → 提示词 → 视频"**，否则提示词里的站位朝向还是旧的

### Q.5 复检（确认真的变好了）

```bash
python scripts/drama.py audit --project {projectId}
python scripts/drama.py coverage --project {projectId}   # 结构复检：剧情有没有被删
# 对比上一轮：P0/P1 下降；台词表里不再有 必须拆镜 / 截断急促 / 偏急；
# coverage 覆盖率 ≥95%；景别分布更丰富；资产引用补齐
```

达标后要落地成视频，走第 6–8 章（调度 → 提示词 → 视频），出片后逐镜检查穿帮。

## D. 精品线：按「场」拍，不按「镜」凑

> 第 1–9 章 + Q 章能做出**连贯的粗剪**。要出**精品**，得再加这一章。
> 粗剪和精品的差别不在画质，在**结构**：剧情有没有丢、场与场有没有咬住、情绪有没有递进。

**精品线的执行顺序**（别照文档章节顺序做）：

```
小说 →〔系统〕script/generate → 剧本基线
     →〔agent〕①按 D.1.5 删冗余/补因果、按场表(D.1)+镜头预算(D.2)校准 → PUT /script/save
     →〔系统〕storyboard/generate → 分镜基线
     →〔agent〕②coverage 补丢失台词(D.3) → ③audit 修时长/动作/声音(Q 章)
              → ④补场间连接件(D.5)/回忆插入镜(D.6) → PUT /storyboard/save
     →〔系统〕staging → prompt → video →〔agent〕⑤串起来看一遍(D.7)
```

> 方块里写〔系统〕的是**平台生成**，agent 不碰内容；写〔agent〕的是**增量修改**。
> 场表(D.1)和镜头预算(D.2)是**判据**，用来判断系统给的结构够不够、该补几镜，不是让你重写。
>
> ⚠️ 上面这套流程里的 `script/generate` 和 `storyboard/generate` **只在"从零开始"时各跑一次**。
> 一旦分镜存在（尤其用户已经精修过），**再也不许重新生成分镜**——见第 5 章的铁律。

### D.0.5 默认路径：**系统生成基线 → agent 增量优化**

**⚠️ 不要让 agent 从零写剧本和分镜。** 平台的剧本/分镜生成和自家模型是**对齐的**（结构化提示词格式、资产绑定、`[Shot N] At mm:ss` 时间轴、台词 `<d>` 标记），外部全量重写会破坏这种对齐，成片观感反而更差——这是实测过的。

**默认路径（99% 的情况走这条）**

```
① POST /script/generate/{projectId}          ← 系统生成剧本基线（质量不差，别推翻）
② agent 审阅剧本：D.1.5 删冗余 / 补因果 / 调场次 → PUT /script/save
③ POST /storyboard/generate/{projectId}      ← 系统生成分镜基线
④ agent 增量修：coverage 补丢失台词 → audit 修时长/动作/声音
              → 补场间连接件(D.5) / 插入镜(D.6) → PUT /storyboard/save
```

**agent 的活是「在基线上做手术」，不是「另起炉灶」**：删多余、补缺口、改节奏、加连接件。
平台已经把 80% 的活干完了，你要解决的是剩下那 20%——那些恰好是决定"粗剪 vs 精品"的部分。

> **顺序铁律：剧本 → 分镜。** 剧本定稿（`PUT /script/save` 并 GET 校验）之后才 `storyboard/generate`。
> 反过来做（先生成分镜再改剧本）会让分镜里的台词和你改后的剧本对不上，`coverage` 直接掉到 90% 以下。
>
> **另外两条操作纪律**（踩过）：
> 1. **每个生成接口只提交一次**，不要连点/重试。同一项目并发跑两个 `storyboard/generate`，
>    会互相覆盖，还可能出现"剧本被冲回旧版"这种鬼现象——实际是竞态，不是平台设计。
> 2. **每次生成/保存之后都 `GET` 回读一次**核对关键字段（场次数、台词数、镜头数），
>    确认自己的改动真的落库了，再往下走。

| 该做（增量） | 不该做（推翻） |
|---|---|
| `coverage` 找出被删的台词，补回去 | 重写全部台词 |
| 给说不完的镜头补时长 | 重排全部镜头与场次 |
| 补场间过渡镜、回忆插入镜 | 自己从零写 60 个镜头 |
| 删重复交代、无画面感叹（D.1.5） | 改掉平台的结构化提示词格式 |
| 调景别/运镜让节奏有起伏 | 自造一套全新的分镜体系 |

**唯一例外**：用户**明确要求**「完全重写剧本/分镜」「不要用系统生成的」。这时才可以全量代写，并且必须跑完 `coverage` 100% + `audit` P1=0 才能交付。

### D.0 先看清"粗"在哪

平台产出为什么像"幻灯片串烧"——三个结构性原因，都不是提示词能救的：

| 原因 | 表现 | 后果 |
|---|---|---|
| **三级压缩，每级无监督** | 小说 → 剧本 → 分镜，每级都在"摘要" | 剧情静默丢失。实测一集：小说 30+ 个情节点 → 剧本 8 场 24 句 → 分镜只剩 18 句（丢 25%）|
| **时长预算反了** | 先定"25 镜 / 90 秒"，再往里塞 8 场 | 每场只剩 3 镜，只能摘要，没有铺垫 |
| **没有"场"的概念** | 25 个镜头平铺，没有场的边界与内部节奏 | 切场硬跳，观感像拼贴 |

**正确顺序是反的**：先算内容需要多少时长 → 再定每场几个镜头 → 最后才是镜头怎么写。

### D.1 第一步：场表（Scene Sheet）—— 写分镜之前先填

不要一上来就写 shots。每一场先填这张表（剧本阶段就该有）：
| 字段 | 要求 |
|---|---|
| 场号 / 地点 / 时间 | 与资产里的场景名**逐字一致** |
| **戏剧功能** | 这场让什么变了？信息 / 权力 / 情绪 / 关系 / 风险，写一项，写不出就是废场 |
| **情绪起点 → 终点** | 例：压抑 3 → 爆发 9。相邻两场不能都平 |
| **时长预算** | 由台词字数推（D.2），不是拍脑袋 |
| **必保台词** | 这场一句都不能删的 1–3 句（信息点 / 爽点）|
| **必保动作** | 观众必须看清的 1 个关键动作（耳光 / 泼水 / 扔项链）|
| **出口钩子** | 这场结束时留什么，让人想看下一场 |

填完自检：**有没有两场功能重复？**（合并）**有没有连续两场情绪都是 5？**（调曲线）

### D.1.5 小说的删与留 —— 改编这一步最重要

**「保留完整小说剧情」是错的判断。** 网文里大量内容是冗余：重复交代、无画面的内心感叹、不推进剧情的过渡、同一情绪反复宣泄。全留下 = 节奏拖死、观众划走。

改编要做的是**合理编排**，不是忠实搬运。判据是「删了会不会坏」，不是「原文有没有」。

**该删（冗余）**

| 类型 | 例子 | 处理 |
|---|---|---|
| 同一信息说第二遍 | 先旁白说"他是我男朋友"，后面对话又说一遍 | 留一处（优先留画面能演的）|
| 无画面的内心感叹 | "我不禁冷笑""我都是要死的人了，怕什么""发疯也是个力气活" | 能转动作就转，转不了删 |
| 解释性旁白 | 观众从画面能看出来的关系、地点、时间 | 删，用镜头交代 |
| 无戏剧价值的过渡 | "我打了车""我走进电梯""我躺下睡了" | 删或压成 1 个镜头 |
| 同一情绪的连续宣泄 | 连着三段都在骂渣男 | 合成一段，取最狠的一句 |
| 重复的形容词堆叠 | "她很美，特别美，美得不像话" | 留一个具体的可见细节 |

**该留（不可删）**

- **因果链**：他为什么动手、邻居为什么站她、她为什么突然发疯。删了因果，后面全变成"突然"。
- **人设根基**：证明"她一直被抢"的具体事例（布娃娃、作文）。这是爽点的地基，删了就只是吵架。
- **情绪转折点**：人物做出决定的那个瞬间，必须有一个镜头。
- **爽点 / 钩子**：反击的台词、结尾的悬念，一个字都别动。
- **关键道具与伏笔**：项链、首饰盒、眼镜——后面要用的东西必须提前出现。

**删留三问（拿不准就过一遍）**

1. 删掉之后，观众会不会**不懂后面某件事**？→ 会不懂 = 必须留
2. 这场戏删掉，**人物的决定会变吗**？→ 不变 = 可删
3. 这句话**能变成画面吗**？→ 能 = 改成镜头（比旁白强）；不能且不推进 = 删

> 一句话原则：**删"感受"，留"事实"；删"重复"，留"因果"。**
> 网文的第一人称吐槽是风格，但连续三段吐槽在视频里就是原地踏步——挑最狠的一句，其余交给表演。

### D.2 镜头预算：从内容倒推，不从镜数倒推

```
每场必须时长 = 必保台词字数 ÷ 4 + 关键动作秒数 + 反应留白(1–2s)
每场镜头数   = ceil(必须时长 ÷ 平均镜长) + 反应镜 + 过渡镜
平均镜长：对话场 4–5s ｜ 动作场 2–3s ｜ 情绪场 5–8s
```

例：一场 4 句台词共 60 字 → 15s；两个关键动作 4s；反应留白 3s → 约 22s → 5–6 镜。

**一集 3–4 分钟是正常的。** 硬压到 90 秒必然丢剧情——按内容给时长，别按"短剧就该 90 秒"给。

### D.3 台词零丢失（硬卡口）

**基准是「剧本」，不是「小说」。** 小说 → 剧本允许并鼓励删冗余（见 D.1.5），那是创作；
但**剧本一旦定稿，剧本 → 分镜就不许再丢**——那是执行失误。

剧本里的每句台词，分镜里必须出现——**要么演出来，要么被角色打断**（打断也要有明确的"打断动作"，不能凭空消失）。

```bash
python scripts/drama.py coverage --project {projectId}
```

输出「场次覆盖表 + 逐句丢失清单 + 覆盖率」。**低于 95% 不许往下走**。

> 实测一集丢 6 句，丢的恰好是"父亲为什么打人""邻居为什么站她"的关键句——剧情跳跃就是这么来的。
> 这一步是整条精品线里性价比最高的：不改一个字，只把丢的补回来，连贯度立刻不一样。

### D.3.5 出片前的资源闸门（缺图不许往下走）

分镜引用的是**资产 id**，不是图片本身。如果资产建了但图没出，提示词和视频都会**静默地**失去参考——
人物脸对不上、场景每个镜头都不一样，而且不会报错。

```bash
python scripts/drama.py preflight --project {projectId}
```

逐镜检查四件事，任一不过就退出码 1：

| 检查 | 触发条件 | 怎么补 |
|---|---|---|
| **调度** | `staging.segments` 为空（跳过了场面调度） | 先跑 `generate-staging`（第 6 章），再生成提示词 |
| **场景** | `sceneAssetId` 为空 / 资产不存在 / **七个视角图全是空** | 出场景图 |
| **角色** | `characterAssetIds` 里某个 id 不存在 / 角色 `imageUrl` 为空 | 出角色图 |
| **道具** | `propAssetIds` 里某个 id 不存在 / 道具 `imageUrl` 为空 | 出道具图 |

**这道闸必须卡在「生成提示词」之前**，不是生成视频之前——因为提示词本身就要绑参考图。

> 踩过：只给主要角色出了图，**群演（顾客甲/乙、邻居甲/乙/丙）漏了**，
> 结果 7 个镜头引用的是没有图的角色，出片时这几镜的人物完全是另一个样子。
> 群演也要出图，除非你**把该角色从镜头的 `characters` / `characterAssetIds` 里删掉**（纯画外音才允许）。

### D.4 节奏：把"场"当乐章，不是当清单

- **全片节拍**：钩子（前 3 秒）→ 第一次冲突 → 升级 → 爆发 → 反转 → 新钩子收尾。
- **每场内部**：进入（定空间）→ 发展（给信息）→ 转折（情绪翻面）→ 出口（留钩）。
- **呼吸**：全片每 60–90 秒要有一次"静"——空镜、停手、长叹、环境声独奏。短剧不是一路喊到底。
- **高潮不加速，反而放慢**：耳光、泼水这类爽点，前一镜"慢半拍"（手抬起的特写），打完"留一拍"（对方的反应 + 周围死寂）。

### D.5 连接件：让剪辑"咬住"（串起来舒服的关键）

场与场之间必须有**物理或听觉的钩子**，否则就是硬切：

| 连接件 | 做法 |
|---|---|
| **动作切** | 上一镜抬手 → 下一镜手落下（跨空间也成立）|
| **视线匹配** | 上一镜人物看向画外 → 下一镜切他看到的东西 |
| **声音先行** | 下一场的声音提前 0.5–1 秒进来（烟灰缸破空声先到，门才开）|
| **同构剪辑** | 两个相似构图并置（医院冷白 → 咖啡店冷白），产生"命运轮回"感 |
| **空镜过渡** | 雨、灯、车流 1–2 秒，给观众换气 |
| **遮挡转场** | 人物走过镜头挡黑，下一镜从遮挡后开始 |

**每换一个场景，就必须有一个连接件。** 没有连接件 = 观众感觉"跳了"。

### D.6 回忆 / 对比戏：不要删，要"降维拍"

平台最爱删回忆和对比（布娃娃、作文、见家长双标），因为没有对应场景资产。可这类戏恰是人设根基和爽点铺垫。三种低成本拍法：

1. **道具特写 + 画外音**——不拍回忆，拍"现在手里的东西"（旧布娃娃、奖状），台词用画外音讲。
2. **同机位换装**——同一构图，换服装/年龄，一秒完成时间跳跃。
3. **插入镜（insert）**——2 秒的手部/物件特写，把抽象信息变成一个可见事实。

原则：**能用 2 秒插入镜交代的，绝不删。**

### D.7 交付前：串起来看一遍（不是逐镜检查）

逐镜查的是"单镜有没有穿帮"，串起来看查的是"整体顺不顺"。过这五问：

1. 有哪一处**要暂停想一下才明白发生了什么**？→ 缺镜头
2. 有哪句台词**没有来由**（观众不知道他为什么这么说）？→ 缺前因镜头
3. 有哪个角色**突然出现**（没交代怎么来的）？→ 缺入场镜头
4. 有哪两个相邻镜头**看着像同一个**？→ 切镜没职责
5. 结尾有没有**想点下一集**的冲动？没有就重做出口钩子

## 1. 建项目 → 建分集（连续剧的**第 1 步**，顺序不能跳）

### 先问用户三个问题（必问，不要自己拍板）

| 问题 | 系统里的选项（**必须传原值**） |
|---|---|
| **视觉风格** `visualStyle` | `真人写实` · `日系动漫` · `3D国风动漫` · `神话仙侠` · `卡通` · `油画` · `水彩` · `像素风` · `赛博朋克` · `古风` · `奇幻` · `电影感` · `其他风格` |
| **画面尺寸** `imageSize` | `16:9` 横屏（电影/视频）· `9:16` 竖屏（短视频）· `1:1` 方形（社交媒体）· `4:3` 传统比例 · `3:4` 竖版图片 |
| **项目类型** `type` | `连续剧`（多集，资产跨集共享）· `AI短剧`（单集独立）· `AI长视频` |

- 选项要**原样呈现给用户选**，不要自己替他决定。
- `visualStyle` 必须传上表**原值**（是 `电影感` 而不是 `电影感写实`）——传不在选项里的值，
  页面下拉会显示空白，后续所有图片提示词的风格锚点也会漂。
- 用户选「其他风格」时，把具体描述写进 `description`，`visualStyle` 仍传 `其他风格`。
- 用户没说清楚就给推荐并说明理由（例如「都市复仇题材建议 `电影感` + `9:16`」），
  等他确认后再建项目，**不要静默选一个就往下跑**。

### 连续剧的流程（顺序不能跳）

**流程是有顺序的：先建项目，再建分集，然后才允许写内容。** 跳过"建分集"，后面全白做。

```
连续剧：① 建项目（父/容器）
        → ② 建分集（第 1 集）      ← 这两步做完才能往下
        → ③ 小说 → ④ 剧本 → ⑤ 资产 → ⑥ 分镜 → ⑦ 调度 → ⑧ 提示词 → ⑨ 视频
                     ↑ 从 ③ 开始，所有接口一律用【分集 id】
```

三条硬规则：

1. **② 没做完，不要开始 ③**。父项目是容器，页面上不显示它的剧本/分镜/视频，打开只会停在"还没有分集"的引导页。
2. **③ 之后一律用分集 id**。①返回的 `parentId` 只用来建分集、查分集列表，不要拿它写小说/剧本/分镜。
3. 资产（角色/场景/道具）是父子共享的：用分集 id 建、用分集 id 查都会自动带出父 + 全部分集的资产；
   但**剧本 / 分镜 / 视频是 per-project 的**，写到父项目上等于没写。

### 连续剧（多集）

```bash
# ① 父项目（容器，只用来挂分集）
POST {base}/project/create
{"name":"剧名","description":"一句话卖点","type":"连续剧","visualStyle":"电影感","imageSize":"9:16"}
→ data.id = parentId

# ② 第一集（必须做，不然后面都没意义）
POST {base}/project/{parentId}/children
{"name":"第1集 集名"}
→ data.id = projectId   ← 从这一步起，novel / script / storyboard / video 全用这个 id
```

**开工前自检一句**：`GET {base}/project/{parentId}/children` 能查到这一集，才继续第 3 步。

### AI短剧（单集）

```bash
POST {base}/project/create  {"type":"AI短剧", ...}
→ data.id 直接就是 projectId，不需要分集
```

创建后把 `projectId` 记进会话上下文，后续所有接口都要它。

## 2. 小说入库与分集规划

**核心原则：内容不许漏，质量不许塌。** 一次做不完全本，就按剧情切成若干集，
建好所有分集、各存各的片段，然后一集一集做——而不是把全本塞进一集、再被压缩掉一半。

### 2.1 先判断要不要分集

| 小说字数 | 分集建议 |
|---|---|
| ≤ 5000 字 | 1 集（约 15–25 镜 / 60–90 秒） |
| 5000–15000 字 | 2–3 集 |
| 15000–40000 字 | 4–8 集 |
| > 40000 字 | 按 5000–8000 字/集切，先规划前 5 集，做完再继续 |

一集 60–90 秒（15–25 镜）比较好控。**集数由剧情断点决定，不是拿字数硬除。**

### 2.2 切分：找剧情断点，不按字数切

1. 通读全文，列出情节点（每 800–1500 字至少一个转折 / 揭示 / 冲突升级）
2. 按「每集 3–5 个情节点 + 结尾一个钩子」分组
3. **断点优先落在悬念处**（刚要揭穿、刚被撞破、话说一半），不要切在一段中间
4. 每集结尾留钩子，让观众想看下一集

### 2.3 建好全部分集，各存各的片段

```bash
# 父项目
POST {base}/project/create  {"type":"连续剧", ...}  → parentId

# 一次把要做的集都建出来
POST {base}/project/{parentId}/children  {"name":"第1集 xxx"}  → ep1
POST {base}/project/{parentId}/children  {"name":"第2集 xxx"}  → ep2

# 每集只存自己那段文本（后续剧本/分镜都基于这一段）
PUT {base}/novel/save/{ep1}  {"content":"<第1集对应的原文片段>"}
PUT {base}/novel/save/{ep2}  {"content":"<第2集对应的原文片段>"}
```

> ⚠️ 字段名是 **`content`**（接口文档写成 `key`，是文档生成错误，已核对源码）。
> 单次 PUT 不超过约 2 万字；超了就把这一集再拆，**不要截断**。

### 2.4 然后逐集跑

每一集重复第 3–8 步（剧本 → 资产 → 分镜 → 调度 → 提示词 → 视频）。
**做完一集交付一集**，让用户看过再继续下一集，避免 10 集全做完才发现风格不对。

> 资产是父子共享的：第 1 集建好的角色/场景/道具，第 2 集用分集 id 查列表就能拿到，
> 不需要重复建（重复建同名资产会让同一角色有两套图，跨集形象就崩了）。

### 2.5 发现只做了小说的一部分？回去重新切分

如果做完发现只覆盖了原文的前 1/3，说明**规划阶段少切了集**。
不要靠"多塞几个镜头"去补——单集超过 25 镜，节奏就塌了，最终质量还不如分两集。
正确做法是回到 2.2 重新切分，补建分集，把剩下的内容挪过去。

## 3. 剧本 —— 第一处创作介入

**先把平台的基线生成出来，再按电影标准重写。** 不要跳过平台生成：它已经抽出了人物/场景/道具的结构化清单，重写时可以直接沿用，省掉一致性对齐。

```bash

{"novelContent":"<本集对应的原文片段>","style":"<风格>","episodeCount":1}
→ data = taskId

# 2) 轮询

→ data.status: pending | processing | completed | failed

# 3) 取基线
GET {base}/script/content/{projectId}

# 4) 你重写后整包保存
PUT {base}/script/save/{projectId}   # body = ScriptData，见下
```

### 重写时的电影标准（逐条过）

> 完整版见 `reference/cinematic-rules.md` 的「一、剧本层」。这里只列必须记住的六条。

- **一场戏只承担一个戏剧功能**：推进 / 揭示 / 反转。功能重复的场次合并。场戏结束时，信息、权力关系、情绪、物理状态、风险至少有一项和开头不同。
- **开场 10 秒必须有钩子**：异常画面、冲突台词、或信息缺口。不要用环境铺陈开场。
- **对白写潜台词**：人物说 A 想要 B。检验方法——把台词拎出来问"这句话想让对方做什么"，答不上来就删。
- **每句台词都要能变成演员的一个动作或表情**，转不成的删掉或改写成动作。这是最有效的去 AI 味手段。
- **删掉所有"交代性对白"**（角色互相解释观众已经知道的事）。
- **人物名 / 场景名 / 道具名**在 `characters/scenes/props/plots` 里必须**完全一致**（后面建资产、分镜引用都靠字符串匹配，差一个字就对不上）。

> 只想优化**已有**剧本时走 **Q.3 ⑦**（体检 → 改写 → 回写 → 复检）。

## 5. 分镜 —— 第二处（也是最重要的一处）创作介入

> ## ⛔ 铁律：分镜一旦生成，**绝对不要"重新生成分镜"**
>
> **成片是由「分镜」生成的，剧本只是中间产物。** 分镜生成完之后，剧本和最终画面就没有关系了。
>
> 1. **已有分镜之后再改剧本，对成片毫无作用**——唯一效果是把剧本留个档。不要在这上面浪费时间，
>    更不要改完剧本再"顺手"重新生成分镜。
> 2. **`POST /storyboard/generate` 是整片覆盖**，会把用户**精修过的分镜全部冲掉**，不可逆。
>    除非用户明确说"推倒重来 / 重新生一版分镜"，否则**一次都不要调**。
> 3. 想优化已有分镜，只有三种手术：**改字段 / 插入镜头 / 删除冗余镜头**（见 Q.3、以及下面的插入删除）。
> 4. 如果用户不了解原理、坚持要改剧本：**可以改剧本，但改完不要重新生成分镜**，
>    要把剧本的变化，用"改字段 / 插入 / 删除"手工落到分镜上。
>    实在拿不准就先问一句："分镜已经做过了，是要我改剧本留档，还是把改动落到现有分镜上？"

```bash
POST {base}/storyboard/generate/{projectId}     → taskId
GET  {base}/storyboard/task/{taskId}            # 轮询
GET  {base}/storyboard/content/{projectId}      # 取基线 shots
# 你逐镜重写后整包保存：
PUT  {base}/storyboard/save/{projectId}
```

### StoryboardData 结构（shots 字段名严格按此）

```json
{
  "title": "第1集 雨夜",
  "summary": "...",
  "shots": [
    {
      "shotNumber": 1,
      "description": "画面里发生什么（谁、在哪、做什么，可见的动作）",
      "shotType": "中景",                  // 远景/全景/中景/近景/特写
      "cameraMovement": "缓慢推镜",         // 固定/推/拉/摇/移/跟/升降
      "characters": ["林砚"],               // 必须是资产名，严格一致
      "location": "老城区巷口",             // 必须是场景资产名
      "propNames": ["旧怀表"],
      "duration": 4,                        // 秒，见下方节奏表
      "dialogue": [{"character":"林砚","text":"...","action":"..."}],
      "soundEffect": "雨声、远处车流",
      "mood": "压抑",
      "selectedSceneView": "wideangle",
      "usePrevVideoRef": true,
      "prevVideoFrames": 5
    }
  ]
}
```

**保存前自检（平台会拒或不报错地丢数据，务必自查）**：

1. `shots` 非空，且镜头数与基线一致（增删镜头要显式说明理由）
2. 每个镜头的 `description` 非空
3. `characters` / `location` / `propNames` 里的每个名字都能在资产列表里查到
4. `duration` 之和 ≈ 目标时长，单镜 **2–15 秒**（15 秒是 H3 官方上限；按语义单元切，不按秒数硬切）
5. `shotNumber` 从 1 连续递增
6. **每镜台词字数 ÷ duration ≤ 5.2**，且单词台词 **≤ 60 字**（超了必须拆镜，否则会截断/急促）

> 这 6 条不用手算：`python scripts/drama.py audit --project {id} --file shots.json` 会全查一遍并给逐条改法（见 Q.2）。

### 镜头语言守则（这是"电影感"的来源）

> 只想优化**已有**分镜时走 **Q**：`audit` 体检 → 逐字段改写（Q.3）→ `save-storyboard` 回写 → 复检。
> **从零写分镜前，先做场表（D.1）和镜头预算（D.2）**，否则一定变成"塞镜头"。
> 写完必须过一遍 `drama.py coverage`：台词覆盖率 <95% 就是在丢剧情。
> 完整版见 `reference/cinematic-rules.md` 的「二、分镜层」与「五、镜头之间的衔接」。下面是最容易做错的五条。

**① 每镜只干一件事**：写出「起点 → 唯一动作 → 终点」。涉及交接、换手、放下的，接触方式与物件落点要在同一条链里，不能让物件在镜外瞬移。终点要能成为下一镜的可信起点。相邻两镜同景别同角度 = 这次切镜没职责，并回一镜。

**② 景别是"观众站在多远"，不是情绪音量旋钮**

| 景别 | 唯一擅长的事 | 代价 |
|---|---|---|
| 远景 / 全景 | 地理、力量对比、孤立感 | 读不到表情 |
| 中景 / 中近景 | 互动、手势、走位（最常见的工作档） | 情绪不够近 |
| 近景 | 决定、证据、被藏住的反应 | 丢了空间参照 |
| 特写 / 大特写 | 一处细节成为本镜唯一事实 | 观众读不到周围 |

判断标准是「必须被读到的信息在哪个尺度」，不是「情绪上来了就切近」。
**竖屏**：宽度只有 16:9 的三分之一，横向排开的信息会挤，改用**纵深分层**（前景桌沿/门框/肩背 → 主体 → 后景），远景与全景少用。

**③ 动作塞多了会被压扁，不会被删掉**

5 秒里写 6 个动作，模型会把每个都压成半秒，看起来像快进——比少写更糟。数一下这一镜要观众**看清**几件事，按秒数判断每件够不够。
修法顺序：删没有故事功能的动作 → 合并能连贯的 → 选一个注意中心，其余人只留反应 → 仍放不下就拆镜。**不要靠"快速""依次"硬塞。**

**④ 镜长从时间线推，不按字数折算 —— 且必须够把台词说完**

排台词 + 声音事件 + 必须看清的动作 → 这条线的长度就是本场时长 → 除以目标平均镜长（3–5 秒）得镜数 → 切点放在换人说话、听者反应、动作变化处。

**硬约束（最容易翻车的地方）**：中文口播舒适 **4 字/秒**、快顶 **5.2 字/秒**。

```
说完所需秒数 = 台词字数 ÷ 4
```

时间不够，人物要么**说到一半被截断**、要么**语速被拉得很急促**——两种都很难看。所以顺序是**先给台词留够时间，再加动作和留白**：

- 台词超了 → 拆到说话者和听者两镜，**不要让人物加快语速**（加速最露馅）
- 一句台词超过 **约 60 字**（15 秒 × 4 字/秒）就注定一镜装不下，**必须拆**
- 拆分点放在**句号 / 呼吸点 / 换气处**，不要把一句话劈成两半

> 判定表、阈值和逐镜台词表见 **Q.2**；`drama.py audit` 会直接列出哪几镜会说不完。

**⑤ 续接开关：默认开着，别乱关**

平台默认 `usePrevVideoRef: true` + `prevVideoFrames: 5`（第 1 镜没有上一镜，为 false）。
这是产品的默认行为，**不要批量设成 false** —— 那等于主动丢掉系统本来就给的连贯性。

只有明确会串戏时才关：换场（空间完全不同）、时间跳跃、蒙太奇段落。关了要在交付说明里写清哪几镜、为什么。

> 写分镜 JSON 时**不要显式写这个字段**，让后端默认值生效；确实要关的镜头才单独写 `false`。

**每 8–12 个镜头要有一次节奏变化**（快切段落 / 长镜头喘息 / 静场）。

## 6. 场面调度（机位段 + 角色朝向）

> ## ⛔ 顺序铁律：分镜 → **场面调度** → 视频提示词 → 视频
> **绝对不允许跳过调度直接生成提示词。** 提示词里的机位、站位、朝向、距离全部来自 `staging.segments`；
> 没有调度时，提示词只能瞎猜——人物站错位、朝向反了、背景方向不对，全从这里开始。
>
> `preflight` 已经把这条做成**硬闸门**：任何一镜 `staging.segments` 为空，直接退出码 1，不许往下走。
> 记住三种必须**重跑调度**的情况：
> 1. 改过分镜 `description`
> 2. 改过 `characters`（加人/减人/换人）
> 3. 改过 `sceneAssetId` 或 `selectedSceneView`
>
> 重跑调度之后，**提示词也必须重新生成**——旧提示词里的站位朝向已经过期了。

```bash
POST {base}/storyboard/generate-staging/{projectId}/batch   # body: [镜头序号,...]（0 起）
GET  {base}/storyboard/task/{taskId}
```

产物写在 `shots[i].staging.segments[]`：

```json
{"fromSec":0,"toSec":2.5,"shotType":"中景","camera":"侧后方 45°，略低于视线",
 "chars":[{"name":"林砚","facing":"朝向画左，身体侧对镜头","gaze":"看向画外右侧","distance":"距镜头 3 米"}]}
```

**你要改的是**：`camera` 写清机位高度与角度（"齐腰高，仰拍 15°"），`chars[].facing/gaze/distance` 三件套齐全且**互相自洽**（朝向与视线不能相反）。多角色时写清**相对距离**。

> 改过 `shots[].description` 之后**必须重新生成调度，再重新生成视频提示词**——提示词引用的就是调度里的站位朝向。

## 7. 视频提示词 —— 第三处创作介入

> 🚦 **生成提示词之前，必须先跑 `preflight`。** 它同时卡两件事：
> ① 每镜有没有**场面调度**（没有就不许出提示词，顺序见第 6 章）；② 分镜挂的资产**图有没有出全**。
> 提示词里的机位/站位来自调度，参考图来自资产——缺哪样都会崩。

```bash
python scripts/drama.py preflight --project {projectId}          # 缺调度或缺图就退出码 1，别继续
python scripts/drama.py preflight --project {projectId} --out miss.json
```

**提示词生成完之后，必须跑台词核对**——分镜台词和提示词里的 `<d>` 台词**逐字比对**：

```bash
python scripts/drama.py promptcheck --project {projectId}
```

> 生成提示词时 LLM 经常把台词写错，而且**不报错**，直接变成成片里的错词：
> 漏一句、只写半句、把词改了（"去除妖邪"→"铲除妖邪"）、**同一句重复写两遍**、或者凭空多编一句。
> 所以只查"有没有中文"不够，要**逐字核对句数、遍数和内容**——本命令按三档报：
>
> | 档 | 判据 | 后果 |
> |---|---|---|
> | **P0** | 分镜某句台词没写进 `<d>`（漏 ≥2 字，或长句里漏字且差异占比 ≥20%） | 成片漏词/错词，**必须重生成** |
> | **P1** | 同一句台词重复写了两遍/多遍（多出 ≥2 字且那几句就是分镜台词）；或 `<d>` 里多出分镜没有的话（≥3 字，多编一句/串入别镜台词） | 人物重复说、或多说一句不该说的话 |
> | **P2** | 个别字有出入（语气词、同义字；短句单字差异归这里） | 不影响理解，可忽略 |
>
> 判定看的是**所有 `<d>` 拼起来的整段文本**，所以重复写在不同 `[Shot N]` 段里同样能抓到；
> 分镜本身有两句一样的台词（角色强调重复）时，提示词照写两遍**不会**误报。
>
> 报告里直接给出「分镜原句 / 提示词原句」对照和漏写、多写的具体字，照着改就行。
> 一句台词允许拆成多个 `<d>`（跨子镜头停顿），**不会**因此误报。
> 修法：只重生成这几镜提示词（`batch-generate-msr-prompt` 只传这几个序号），再跑一遍本检查。
> 本地分镜 JSON 也能查：`--file sb.json`（此时不必给 `--project`）。

```bash
POST {base}/storyboard/batch-generate-msr-prompt/{projectId}   # body: [镜头序号,...]
GET  {base}/storyboard/task/{taskId}
```

生成的提示词写在 `shots[i].h3VideoPrompt`（H3 工作流）或 `msrVideoPrompt`（旧 MSR 工作流）。

### H3 是**结构化长提示词**，不要压缩

平台生成的是 3000–6000 字符的英文结构化提示词，固定五节，**顺序和标记都不能动**（模型靠它绑定参考图）：

```
subject_definitions:   每个 <Subject N> 的定义 + "shown in <Picture N>"
summary:               [reference generation] 这段要发生什么
retention_analysis:    <Subject N> 出现在哪些 [Shot N]、保留强度（fully_preserved / weak_reference）
detailed_description:  风格 + 逐段 "[Shot 1] At 00:00.000 ..." 运镜/光/动作/台词
overall_soundscape:    环境底噪 + 动作音效
non_diegetic_music:    配乐（通常 N/A）
```

改写要点：

- 台词必须留在 `<d>[Chinese] ……</d>` 里，**标签和语言标记别删**；换语种要同步改 `[Chinese]`
- `[Shot N] At mm:ss.mmm` 的时间点必须落在本镜 `duration` 内——**改过时长就必须重新生成提示词**，否则时间轴还是旧的
- 改就**逐句改英文描述**，别重写成中文短句、别删 `<Subject N>` / `<Picture N>` 绑定

> 踩过：按"越短越好"把 H3 提示词压成 60 字，等于把主体定义和参考图绑定全删了，人物直接跑偏。

### 如果是旧的 MSR 短提示词（`msrVideoPrompt`）

那种才是短文本，结构 `静态锚点 → 起点 → 唯一动作 → 次级反应 → 运镜 → 声音 → 终点`，60–120 字为佳。逐项：
镜头（焦段/机位/运动）、光（方向+质感，别写"光线充足"）、色、材质/细节、动作节拍（动词具体）、情绪外化、声明画面内不生成字幕文字。

> 只优化**已有**提示词时见 **Q.3 ⑥**；改 `description` 后必须重跑调度再重写提示词。

## 8. 生成视频

> 出片前确认 `preflight` 已经通过（D.3.5）。提示词生成完之后如果又加了角色/道具，要重新跑一次。

```bash
POST {base}/storyboard/generate-msr-video/{projectId}/shot/{shotIndex}?megapixels=0.2
POST {base}/storyboard/batch-generate-msr-video/{projectId}?megapixels=0.2   # body: [镜头序号,...]
GET  {base}/storyboard/task/{taskId}
```

**抽卡策略**（省钱且质量可控）：

1. **先用 `megapixels=0.2`（最低档）跑一遍全片**，只为验证构图/动作/表演对不对——速度最快，结论一样有效
2. 只对"能用但不够好"的镜头调提示词重跑（仍用 `0.2`）
3. 定稿镜头再用 `1.0` 或 `2.0` 重出高清

> 抽卡阶段不要用 0.4 及以上：那只是白等时间，判断"构图对不对"0.2 完全够用。
> **0.2 跑通 → 改提示词 → 定稿升档**，这是唯一该走的顺序。

工作流选择（`GET /storyboard/{projectId}/video-workflow/options`）：

| 工作流 | 适合 |
|---|---|
| `h3_r2v` 官方参考图生视频 | 通用镜头、单遍采样、最快 |
| `h3_ercai` 二采 | 对话/情绪/细节镜头，画质最好、最慢 |
| `h3_wuxi` 武戏 | 动作/打斗镜头 |

可以按镜头逐个指定：`PUT /storyboard/{projectId}/shot/{idx}/video-workflow {"workflow":"h3_wuxi"}`，其余跟随项目默认。

### 审片（必须做）

出片后逐镜检查：人物是否一致、动作是否完成、有没有穿帮（多手、脸部畸变）、首尾是否能接。**不合格的镜头改提示词重跑，不要凑合**——一个穿帮镜头会毁掉整段沉浸感。

### D.8 出片后必须主动说的「友情提示」

视频生成完、导出前后，**主动**告诉用户哪几镜可能不满意，不要等用户来问。照这个意思说：

> 这版我看下来，这几个镜头可能不满意：镜 X（问题）、镜 Y（问题）……
> 你确认哪几镜要改，把现象告诉我就行——我改分镜描述，只重跑这几镜，不用整片重来。

按大量实测，**最严重的问题**是下面这个，逐镜检查时就盯它：

| 问题 | 表现 | 怎么发现 |
|---|---|---|
| **人物站位 / 朝向不对** | 谁在左谁在右反了；身体朝向、视线方向和描述不符；多人同框时挤在一起或背对不该背对的人 | 多人同框的镜头，逐个对照 `description` 里的「左侧/右侧/面向/背对/看向」；重点看正反打和三人以上的镜头 |

**给清单，别笼统说"有几镜不行"**：镜号 + 现象 + 打算怎么改 `description`，让用户只需要回答"改这几镜"。
用户只给现象就够了——改描述、重生成提示词、只重跑这几镜，是 agent 的活。

## 9. 交付

```bash
GET {base}/storyboard/export-videos/{projectId}     # 打包 ZIP
```

> 不做视频超分/高清放大。H3 直接按 `megapixels` 出片，画质由生成阶段决定；
> 需要更高画质就定稿后换高档位（1.0 / 2.0）重出，而不是后期放大。

## 异步任务与轮询（统一规则）

平台所有重活都是异步的，接口立刻返回 `taskId`：

| 任务类型 | 查询接口 |
|---|---|
| 剧本 | `GET /script/task/{taskId}` |
| 分镜 / 视频 / 调度 / 提示词 | `GET /storyboard/task/{taskId}` |
| 资产图片 | `GET /asset/image-task/{taskId}` |
| 人物音色 | `GET /asset/voice-task/{taskId}` |
| 对白克隆 | `GET /storyboard/voice-task/{taskId}` |

- `status`: `pending` → `processing` → `completed` / `failed`
- 轮询间隔 5–10 秒；剧本/分镜生成可能 5–15 分钟，视频单镜 3–10 分钟
- `failed` 时读 `message`/`errorMessage`，**不要盲目重试**——先判断是配置问题（模型没配、资产缺图）还是内容问题（提示词触发审核）
- 刷新页面后可用 `GET /storyboard/running-tasks/{projectId}` 找回在跑的任务
- **轮询脚本被工具超时打断时，最后一行只是中途快照**。判定"卡住/失败"之前必须重新查一次任务状态 + 逐镜状态 + ComfyUI 队列（见下方验收清单 ②）

## 验收清单（每次交付前必须过一遍，都是踩过的坑）

### ① 顺序对不对：分集是不是在写内容之前就建好了

正确顺序只有一条：**建项目 → 建分集 → 写内容**。检查三件事：

```bash
GET {base}/project/{parentId}/children     # 分集存在
GET {base}/storyboard/content/{分集id}     # 内容在分集 id 下
GET {base}/storyboard/content/{parentId}   # 应该是空的；不空说明写错层级了
```

> 踩过：建完项目直接写小说/剧本/分镜，等发现才补建分集，用户点进分集看到空白，
> 只能事后迁移一遍。**根因是顺序错了，不是迁移没做**——第 1 步就把分集建好，根本不存在迁移这件事。
> 如果已经写错层级，补救是把父项目的数据复制到分集（小说/剧本/分镜三份都要），
> 但这是返工，别把它当正常流程。

### ② 任务到底完没完：三方交叉验证

不要凭一次轮询快照下结论。工具超时被打断时，最后打印的那行只是**中途数字**，不是结果。

| 看什么 | 判据 |
|---|---|
| 批量任务 | `GET /storyboard/task/{id}` → `status=completed` |
| 逐镜检查 | 每个 shot 的 `videoStatus == completed` 且 `videoUrl` 非空 |
| 渲染端队列 | ComfyUI `GET /queue`，`running` 和 `pending` 都为 0 |

三者一致才算完。三种不一致的含义：
- 队列空 + 镜头未完成 → **有镜头失败了**，去看 `errorMessage`
- 队列在跑 + 镜头未完成 → 还在生成，继续等
- 任务 completed + 镜头未完成 → 批量任务提前退出，逐镜补跑

> 踩过：轮询脚本被工具超时打断，最后一行停在「16/18」，我据此判断"卡住了"，
> 实际 18 镜早就全部完成。判定状态前一定要重新查一次，不要引用被截断的输出。

### ③ 不要覆盖系统默认值

写 `StoryboardData` 时**只写你确实想改的字段**。有默认值的字段留空，让后端默认生效：

| 字段 | 系统默认 | 说明 |
|---|---|---|
| `usePrevVideoRef` | **true** | 传上一镜视频做参考 |
| `prevVideoFrames` | **5** | 取上一镜末 5 帧 |
| `selectedSceneView` | 按场景模式 | 场景图视角 |

> 踩过：给 18 个镜头全部显式写 `usePrevVideoRef: false`，把系统默认的续接关掉了，
> 成片全是硬切、镜头之间跳变。用户要的"默认行为"被我擅自改掉了。
> **改默认值之前先查后端 DTO 的注释**，不要按自己的理解动。

### ④ 成片完整性

- 每镜 `videoUrl` 非空、`videoStatus=completed`
- 分镜 `duration` 之和 ≈ 成片总时长
- 有失败镜头要单独重跑，**不要带着缺口交付**
- 交付时把"哪些镜头关了续接、为什么"写清楚

### ⑤ 台词说得完吗（一镜能不能把话说完）

```bash
python scripts/drama.py audit --project {分集id}    # 看「台词 vs 时长」表
```

- 表里**不能有** `必须拆镜` / `截断/急促` / `偏急`
- 有就按提示补时长（提到 `字数 ÷ 4`）或拆镜，然后复检一次

> 踩过：把 60 多字台词塞进 15 秒镜头，成片里人物语速快得像二倍速，或者后半句被直接吞掉。
> 一开始以为是模型问题，其实是**时长根本不够**。判定标准只有一条：`字数 ÷ 时长 ≤ 5.2`，且单镜 ≤ 60 字。

## 常见坑（都会静默失败）

1. **连续剧忘了建分集**——小说/剧本/分镜全写进父项目，用户打开页面只看到"还没有分集"的引导页，等于白做。
   必须 `POST /project/{parentId}/children` 建出第一集，之后**所有接口都用分集 id**。
2. **`X-Token` 不是 Bearer**——写错会一直 401
3. **`code != 0` 就是失败**，哪怕 HTTP 200（注意：实测成功码是 **200**，文档写的是 0，脚本两种都放行）
4. **小说保存字段是 `content`**（文档误写 `key`）
5. **资产名与 shots 里的引用必须逐字一致**，否则镜头生不出图（不会报错，只是没图）
6. **分镜保存是整包覆盖**——只传改动的镜头会把其他镜头删掉。正确做法：先 GET 全量 → 改 → 整体 PUT 回去
7. **改过镜头描述就要重跑"调度 → 提示词 → 视频"**，否则提示词里的站位朝向还是旧的
8. **单镜上限 15 秒（H3 官方），不要为了"画质更稳"全部压到 8 秒以内**——长对白拆碎反而更难接
9. **`usePrevVideoRef` 默认 true，不要批量设 false**——后端默认就开（上一镜末 5 帧），
   只有换场、时间跳跃、蒙太奇才关。写分镜时别显式写这个字段，让默认值生效。
10. 换了模型/工作流后**需要重启后端服务**（模板在 classpath 里）
11. **跳过建分集直接写内容**——顺序必须是「建项目 → 建分集 → 写内容」。跳过第 2 步，
    小说/剧本/分镜会写到父项目上，页面永远看不到，只能事后返工迁移
12. **把被截断的轮询输出当结论**——脚本超时被打断时最后一行是中途数字，判定"卡住/失败"前必须重新查一次
13. **擅自覆盖有默认值的字段**——`usePrevVideoRef` / `prevVideoFrames` / `selectedSceneView` 等，
   系统有默认值就不要显式写；要改先查后端 DTO 注释
14. **台词长度和分镜时长不匹配**——`台词字数 ÷ 时长` 超过 **5.2 字/秒**，人物就会截断或急促；
    单句超过 **约 60 字**（15 秒 × 4 字/秒）一镜根本装不下，**必须拆镜，加时长无效**。
    `audit` 的「台词 vs 时长」表会逐镜标出来（见 Q.2）
15. **资产图没出完就生成提示词/视频**——分镜引用的是 id，图缺失时**不报错**，只是那几镜没有参考，
    人物和场景每个镜头都不一样。**群演最容易被漏**（顾客甲乙、邻居甲乙丙）。
    生成提示词前必须跑 `preflight`（D.3.5），缺图先补，或把该角色从镜头的 `characters` 里删掉
16. **提示词里的台词和分镜对不上**——H3 的台词只认中文原句（`<d>…</d>`）。提示词生成经常
    只写 `a voice speaks one line` 不给原句（出片乱念/没声），或者漏一句、只写半句、改词、
    同一句重复写两遍、多编一句——**全都不报错**，直接变成成片里的错词/重复台词。
    生成完提示词必须跑 `drama.py promptcheck` 逐字核对（漏/多/改写分三档报，见第 7 章）
17. **分镜已生成后又"重新生成分镜"**——`POST /storyboard/generate` 是**整片覆盖**，会把用户精修过的
    分镜全部冲掉，不可逆。成片只由分镜决定，剧本改了对画面没有任何作用。
    优化已有分镜只能**改字段 / 插入镜头 / 删除冗余镜头**（见第 5 章铁律）

## 不要做的事

- 不要手动编造 `id`、`videoUrl`、`imageUrl`——这些由平台生成
- 不要在 POST/PUT 里加减字段（后端用的是固定 DTO，多余字段会被忽略，缺失关键字段会写坏数据）
- 不要为"更好的效果"擅自改 `shotNumber` 顺序后不更新 `shots` 数组顺序
- 不要在一次会话里跑完整部 20 集——先做**第 1 集 1 个完整片段（10–15 镜）**，让用户确认风格后再批量
